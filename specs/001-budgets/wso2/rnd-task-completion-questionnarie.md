| Short description about the task | Adds **Budgets** to the API Platform AI Gateway. A budget is a fixed USD amount for a set of owners over a UTC calendar period (day, ISO week, month), in Enforce or Monitor mode, with up to five warning thresholds. Its first owner is the AI Workspace context it is created in (the organization, or a project); further owners — a project, an LLM provider, an LLM proxy, an application, or any claim in the caller's verified token such as team or user — can be appended, each one or more specific values (any of which matches, sharing one allowance) or "each" (a separate allowance per value), and a request counts only when it matches all of them. A new gateway system policy enforces budgets in the request path of every AI route, and changes take effect without redeploying anything. Spend is counted only in a shared Redis that is required wherever budgets are enforced; the control plane stores definitions only. Threshold crossings are detected by the gateway and carried on analytics events to Moesif, where one organization-wide alert rule delivers warnings and one Budget Usage card plus a Budget filter on the existing LLM Analytics page show usage. The AI Workspace gets a configuration-only Budgets page with links to that usage. |

| Security |  |
| Explain the security aspects of the task. For example how the services etc. are secured. | Public budget endpoints require an OAuth2 JWT; writes need `ap:budget:manage`, reads need `ap:budget:read` or `ap:budget:manage`. The organization always comes from the verified token; cross-organization access returns the same 404 as a missing resource. Request DTOs are decoded strictly and immutable fields are rejected on update; error bodies are generic. Read-only mode is enforced in the service and repository layers. Gateway-side traffic reuses the existing authenticated gateway websocket and gateway token; no new inbound internal endpoint exists. Redis connections support ACL authentication and TLS / mTLS; secrets come from environment or Kubernetes Secrets; claim values are hashed in Redis key names. Enforce-mode budgets fail closed when Redis is unreachable unless a gateway is set to fail open. No claim values, keys, tokens or Redis passwords are logged at INFO or above, and metrics carry no user or claim labels. Client-facing headers are platform-neutral. Known PII exposure: callers' claim values (often email addresses) are sent to Moesif as `budget_owner_values` and shown on the Budget Usage card; masking is open. Full detail is in the Security Impact Review questionnaire. |

| Performance |  |
| Why do you think this doesn’t impact the performance of the existing capabilities of the product? If this has an impact, has it been discussed with the leads. Provide details. | With `budgets.enabled = false` (the default) the policy is not injected, so there is no change. With budgets enabled, the policy does nothing unless the route is an LLM provider / proxy and the organization has budgets. A budgeted request costs two pipelined Redis round-trips (one read at admission, one write at response end), plus one `SET NX` only when a threshold is reached; target added latency is under 5 ms at the 95th percentile with Redis in the gateway's network region (SC-008). The response side is streaming-capable, so token streaming is preserved. Definitions reach gateways through the existing push path and are read from memory. Discussion with leads on performance specifically: NOT ANSWERED; the multi-region Redis latency question is open with architecture leads. |

| Migration Impact |  |
| Explain why this task doesn’t impact the smooth upgrade flow of the product. | The schema changes are a new table and a nullable column added by idempotent DDL at startup, and the previous release runs unchanged against the upgraded schema, so rollback is safe. Rollback options: disable or delete budgets (enforcement stops within seconds) or set `budgets.enabled = false`; Redis keys expire on their own. Mixed versions: gateways older than this feature log and drop the new `budget.*` websocket messages and keep serving traffic, but do **not** enforce budgets; whether the platform should warn about such gateways is open. Already-deployed LLM proxies need a redeploy before project budgets match their traffic. |
